# Business Blueprints — Product Types

**Status:** Canonical product-format taxonomy  
**Parent opportunity:** **Business Blueprints**  
**Issue:** #72  
**Rule:** **A product type is not a parent business opportunity.**

## Read this first

DRF has one parent opportunity for packaged digital business IP:

> **Business Blueprints**

A Blueprint can be delivered in several product formats. The file format, builder, marketplace or storefront does **not** create a new parent business.

```text
PROVEN OUTCOME × NICHE
        ↓
BUSINESS BLUEPRINT
        ↓
choose the best product format(s)
        ↓
choose compatible distribution channels
        ↓
sell / deploy / measure
```

## Product types

| Product type | What the buyer receives | Typical specialist channels | Parent opportunity |
|---|---|---|---|
| **Complete operating-business Blueprint** | Playbook, SOPs, pricing, scripts, workflows, templates, implementation instructions and proof boundaries | Whop plus general digital-product storefronts | **Business Blueprints** |
| **Website + revenue launch kit** | Reusable site/landing assets plus lead capture, CRM/quote/booking flow, tracking and deployment instructions | Framer, Webflow plus general digital-product storefronts | **Business Blueprints** |
| **Notion / database operating system** | Databases, dashboards, CRM/project/recruitment workflows and operating instructions | Notion Marketplace plus general storefronts | **Business Blueprints** |
| **Workflow / automation pack** | Automations, recipes, configuration, SOPs and implementation instructions | Whop, Gumroad, Contra and compatible specialist channels | **Business Blueprints** |
| **Prompt / agent / Skill pack** | Prompts, agent instructions, Skills and workflow components | PromptBase, Whop, Gumroad, Contra where policy fit allows | **Business Blueprints** |
| **Software / licence / API component** | Reusable software, licence, app or API capability that forms part of the operating system | Lemon Squeezy, Shopify, GitHub Marketplace, RapidAPI where applicable | **Business Blueprints** |
| **Playbook / guide / checklist bundle** | Documented operating knowledge and deployment assets | Gumroad, Payhip, Whop, Contra and owned storefronts | **Business Blueprints** |

A single Blueprint can contain more than one product type.

## Qualification rule

An asset becomes a Business Blueprint SKU only when it has:

1. a clearly defined underlying **Outcome × Niche**;
2. evidence that the operating logic is useful, not generic filler;
3. a repeatable core that can be reused without rebuilding from zero;
4. explicit setup, inputs, boundaries and failure modes;
5. rights-safe assets and channel-compatible packaging;
6. a measurable buyer outcome or deployment objective;
7. a version-controlled canonical source.

The packaged product still needs its own buyer-demand test. Proof that a service works does not automatically prove that strangers will buy the digital product.

## Naming rule

Do **not** create a parent opportunity named after:

- a website builder;
- a template format;
- a marketplace;
- a storefront;
- a CRM;
- an AI model;
- a file type.

Those belong downstream as **product format, delivery rail or distribution channel**.

## Website / launch-kit treatment

Website and launch-kit assets are one product type inside Business Blueprints. They are useful when a proven business system naturally needs a conversion-ready digital front end, but they are not independently ranked as another DRF parent business.

See [`product-types/website-and-launch-kits.md`](./product-types/website-and-launch-kits.md).
