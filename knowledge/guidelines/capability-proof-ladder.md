# Guideline — Capability Proof Ladder

## Principle

Never infer operational or commercial capability from installation, authorisation or a green upstream step.

```text
installed / authorised / connected
≠ permission granted for every operation
≠ operation successfully demonstrated
≠ commercially useful outcome
```

## Four execution layers

```text
1. CONTROL SURFACE
   founder / ChatGPT / GitHub / business system

2. TRIGGER + DETERMINISTIC AUTOMATION
   Issue / event / workflow / scheduler / API

3. AGENTIC EXECUTION
   model / agent / specialist executor

4. DELIVERY + EVIDENCE
   message / record / branch / PR / booking / payment / report
```

A successful trigger proves only the layer it actually executed.

## Failure rule

Diagnose the **first broken layer**. Do not describe an entire chain as simply “working” or “broken”.

## Commercial extension

For revenue operations, technical delivery is still not the final proof:

```text
workflow ran
→ intended action happened
→ prospect/customer received it
→ meaningful response occurred
→ qualified next step occurred
→ revenue signal / cash occurred
```
