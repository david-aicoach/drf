# DRF Recurring Intelligence History

**Status:** Canonical cross-portfolio control-log area  
**Governing stage:** [77.5] #82

This folder records concise run-level history for DRF recurring research loops and their durable GitHub contracts.

It is not a substitute for:

- opportunity dossiers under `businesses/<opportunity>/`;
- ranked niche evidence under `research/niches/`;
- the joined V3 portfolio register;
- GitHub Issues and verification evidence.

## Files

- [`DISCOVERY-RUNS.md`](./DISCOVERY-RUNS.md) — one row per completed, partial or failed discovery run.
- [`DISCOVERY-REJECTIONS.md`](./DISCOVERY-REJECTIONS.md) — one concise row per rejected/held candidate, with reason and reconsideration trigger.
- [`REFRESH-RUNS.md`](./REFRESH-RUNS.md) — one row per portfolio refresh or event-triggered refresh.
- [`AUTONOMOUS-AI-REVENUE-OPERATIONS.md`](./AUTONOMOUS-AI-REVENUE-OPERATIONS.md) — canonical monthly research contract for the vendor-neutral Autonomous AI Revenue Operations Business-in-a-Box parent opportunity. It requires durable GitHub writeback; chat-only output is failure.
- [`AUTONOMOUS-AI-REVENUE-OPERATIONS-RUNS.md`](./AUTONOMOUS-AI-REVENUE-OPERATIONS-RUNS.md) — concise audit history for those monthly runs.

## Rules

1. Never invent a run or candidate result.
2. Add a row only after a real run begins and its status is known.
3. Use the stable run ID defined by the governing workflow/contract when one exists.
4. Detailed evidence belongs in the current monthly research/opportunity dossier; these files hold concise navigation and audit history.
5. Rejected candidates remain outside `businesses/PORTFOLIO-V3.md` unless later reconsidered and advanced.
6. A partial or failed run does not replace the last successful canonical conclusion.
7. **Recurring research is incomplete if durable GitHub writeback required by its contract fails. Chat is a summary surface, not the datastore.**
8. Do not store credentials, personal/customer data or proprietary interview content here.
9. Archive older rows only when volume impairs use, retaining stable links and summary counts.

## Canonical processing

```text
scheduled research trigger
→ read current DRF canon
→ external research / evidence
→ detailed monthly or opportunity-owned research
→ score/portfolio reconciliation when justified
→ concise run-history row
→ founder chat summary
```

The dashboard may show last-success, staleness and run-health summaries derived from these records. It must not write business truth back into them.
